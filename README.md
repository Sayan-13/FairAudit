## 1. What this project does (plain English)

We take the **UCI Adult** census dataset (about 48,000 people) and train classical machine learning
models to predict whether a person earns **more than $50K a year**. Then we check whether the models
treat groups of people differently:

* Do the models say "high income" more often for **men** than for **women**?
* Do they do this for different **race** groups? For different **age** groups?
* Is the difference real, or could it be random noise? (statistical tests)
* Does removing the `sex` and `race` columns fix it? (spoiler: no)
* Can known **bias-mitigation** techniques reduce the gap, and how much accuracy do we lose?

**Main findings** (all numbers are from our own runs, test set of 12,198 people):

| Finding | Number |
|---|---|
| Best model: gradient boosting | 87.0 % accuracy, F1 0.707 |
| It predicts ">50K" for men vs women | 26.4 % vs 8.3 % (gap 0.181) |
| Among people who *truly* earn >50K, how many it finds (men vs women) | 66.8 % vs 57.7 % (gap 0.091) |
| Is the gap statistically significant? | yes, p < 1e-10 for every model |
| Remove sex/race columns | gap barely moves (0.171): other columns act as proxies |
| Biggest gap of all: by age group | 2.7 % of under-30s selected vs 34.9 % of 45–59 (gap 0.321) |
| Best "cheap" fix for equal opportunity: group thresholds | gap 0.075 → 0.002 for only 0.2 pt accuracy |
| Best fix for demographic parity: reweighing | gap 0.171 → 0.101 for 0.6 pt accuracy |
| Strongest fixes (in-processing, Hardt post-processing) | smaller gaps but 1–2.4 pt accuracy loss and they break predictive parity |

Read `docs/Viva_Guide.pdf` for a full explanation of every concept, method and result (made for viva preparation).

## 4. What exactly was done (step by step)

1. **Data.** Load UCI Adult from OpenML (48,842 rows). Drop 52 duplicate rows and the `fnlwgt` column (a census weight, not a personal attribute). Missing values (`?`) become NaN and are filled inside the model pipeline (median for numbers, most frequent for categories), fitted on training data only. Add an `age_group` column (<30, 30–44, 45–59, 60+) for auditing.
2. **Split.** 25 % test (12,198), then the rest split 80/20 into 60 % train (29,273) and 15 % validation (7,319). Stratified on the label, seed 42.
3. **Models.** Logistic regression, linear SVM, random forest, gradient boosting (`HistGradientBoostingClassifier`). Each trained twice: **with** sex/race as inputs and **without** them. Hyperparameters picked by 3-fold cross-validation on the training set (F1 score).
4. **Loss curves** (required by the professor). Logistic regression trained by SGD, log loss per epoch (40 epochs); gradient boosting, log loss per boosting iteration (400). Training and validation loss both recorded.
5. **Fairness audit** on the test set, per group (sex, race, age group, sex×race): selection rate, TPR, FPR, FNR, PPV, accuracy. Gaps: demographic parity (selection rate), equal opportunity (TPR), FPR, predictive parity (PPV).
6. **Statistics.** 95 % bootstrap confidence intervals (1,000 resamples) for every gap; two-proportion z-test and chi-square test on selection rates.
7. **Mitigation** (on gradient boosting and logistic regression, starting from the "without sex/race" version), target attribute = sex:
   * Pre-processing: **reweighing** (Kamiran & Calders), **disparate impact remover** (Feldman et al.)
   * In-processing: **exponentiated-gradient reductions** (Agarwal et al.) with a DP constraint and with an EO constraint (via `fairlearn`)
   * Post-processing: **group-specific thresholds** (equalize TPR, thresholds chosen on validation), **equalized-odds post-processing** (Hardt et al., via `fairlearn`)
   * Also reweighing + thresholds combined.
8. **Ablations.** (a) with vs without sex/race, (b) across the 4 model families, (c) before vs after each mitigation.
9. **Report.** IEEE two-column, 6 pages, 18 references. Sections: Intro & Related Work · Methodology (+ diagram) · Experimental Settings · Results & Ablations · Conclusion.

## 5. Rules we followed

* Classical ML only, no neural networks. (`fairlearn` only wraps sklearn models.)
* Seed 42 everywhere. Test set used once per final model; all tuning on training data via cross-validation.
* All preprocessing inside an sklearn `Pipeline` so nothing leaks from validation/test into training.
* No number in the report is typed from memory: each comes from `experiments/results/`. Run `check_report_numbers.py` after changing anything.
* Report text is our own words; references are real papers but **must be re-verified on Google Scholar** before submission.

## 7. Known limitations (also stated in the report)

* One dataset, from the 1994 US census. Results describe that data, not today's world.
* `sex` is binary in the data; three race groups have only ~100 test rows, so their estimates are noisy. Intersectional cells can be as small as 34 rows.
* Mitigation was applied to sex only; race and age gaps are mostly unchanged by it.
* Our disparate impact remover repairs numeric columns only (categorical proxies are untouched, which is why it barely helps).
* Not done from the proposal: Prejudice Remover (we used the Agarwal reductions method instead) and the German Credit dataset (we chose Adult).
* Experiments were run on a laptop (Apple M4, CPU), not on Colab; the code is identical and runs on free Colab in a few minutes.
